# Run the SPHEREx survey from your browser

The private Kaggle notebook runs Python, reads NASA FITS data into temporary remote storage, and executes DeepTrace. Supabase stores compact checkpoints and scientific evidence. SLOWTRACE X displays that evidence and can queue a bounded field search. Browser setup and viewing work with your computer off between visits. The source ZIP contains program files and a small pilot provenance manifest.

## Check the free plans

- In [Kaggle](https://www.kaggle.com/code), open a private Python notebook. In **Settings → Session options**, choose **Accelerator → None** and check that **Internet** is available. Complete Kaggle's account verification if prompted. Check **Settings → Scheduling** for recurring runs, and your account's displayed compute allocation. Kaggle documents 4 CPU cores, 30 GB RAM, a 12-hour CPU session, 20 GB of savable output, and extra session-only scratch. Those are published reference limits. Kaggle does not publish a universal weekly/monthly CPU entitlement in the notebook guide. The notebook reports what it sees at runtime. The bounded research workload uses Kaggle's built-in notebook workflow and follows published quota and access limits. [Notebook documentation](https://www.kaggle.com/docs/notebooks) · [Acceptable use policy](https://www.kaggle.com/aup)
- In [Supabase](https://supabase.com/dashboard), create a dedicated **Free** organization and project. Its plan is $0 with 500 MB of database space and 5 GB of regular egress. Free projects may pause after a week of inactivity. The worker refuses new scientific work at 245 MB of database size, with room for transaction overhead. If the provider restricts access, retain the records and resume after access returns. Reaching the database-size threshold requires a verified export or another genuinely free storage arrangement before continuing. [Pricing](https://supabase.com/pricing) · [Free project pausing](https://supabase.com/docs/guides/platform/free-project-pausing)
- In [Vercel](https://vercel.com/dashboard), open the team that owns SLOWTRACE X and verify **Settings → Billing** shows **Hobby**. Only deploy this release to a confirmed no-card Hobby project. Service policies and free limits can change. If a provider asks for a payment method or an upgrade, stop setup. [Hobby plan](https://vercel.com/docs/plans/hobby)

## Set up checkpoints in Supabase

1. Open the new project's **SQL Editor → New query**. Paste the full contents of `schema.sql` and click **Run**. Use a fresh project for the pilot.
2. In **Connect** and **Settings → API Keys**, find the **Project URL**, the **publishable key** (`sb_publishable_…`), and create a dedicated **secret key** (`sb_secret_…`) for the notebook. Keep the secret key in Kaggle Secrets. The project URL and publishable key may go into Vercel.
3. After the pilot, to let yourself queue detections, open **Authentication → Users → Add user → Create new user**. Set your email and a dedicated password, auto-confirm the user if the dashboard offers it, and copy the user's UUID. Disable new-user signups in the project's Auth settings if you're the only operator. Then run the following in **SQL Editor**, substituting the copied UUID. The password belongs only in the Auth dashboard and the website sign-in form.

```sql

values ('REPLACE-WITH-AUTH-USER-UUID')
on conflict do nothing;
```

## Run the two-part remote pilot

1. In Kaggle, create a **private** Dataset and upload `slowtrace-kaggle-source.zip`. Add that dataset as an input to a **private** notebook. Import `slowtrace-kaggle.ipynb` with the notebook editor's **File → Import Notebook**. Choose **Python**, **Accelerator → None**, and **Internet → On**.
2. In **Add-ons → Secrets**, add and attach `SLOWTRACE_SUPABASE_URL` and `SLOWTRACE_SUPABASE_SECRET_KEY`. Copy their values directly from the Supabase dashboard.
3. Keep `MODE = 'pilot'`, `BATCH_PRODUCTS = 20`, and `PILOT_STOP_AFTER = 7`. Use **Save Version → Save & Run All**. The saved run checks access to the public archive and pauses after committing seven genuine products. The run log and database should show seven unique preprocessed products if all seven succeeded.
4. In **SQL Editor**, run `select public.slowtrace_survey_status();`. Check its metrics and latest checkpoint. Back in Kaggle, set `PILOT_STOP_AFTER = None` and save and run a second version. Check that unique preprocessed products only increase for newly processed observations. The pilot expects at least 10 verified products and a completed motion group. Compare measured CPU seconds, peak RAM, scratch bytes, transferred bytes, and FITS source IDs across both runs. If the result is incomplete, investigate the run before enabling any schedule.
5. For a harder recovery check, cancel a saved run only after it commits a product. Wait for the five-minute lease to expire, then start another saved run. It should reclaim unfinished work and preserve the completed count. The run can reread an image whose result was interrupted before commit.

Start with the provided caps of one CPU computation thread, up to 8 GiB of worker address space, 2 GiB of temporary scientific files, 2 GiB of science transfer, and 45 minutes of worker time. Lower the notebook settings if the account permits less. Dependencies and the connectivity probe run separately and consume a small amount of additional Kaggle resources. The notebook leaves the FITS files in temporary Kaggle scratch only while needed. On normal completion and handled interruption, it deletes them. Kaggle disposes of remote scratch if it terminates the session.

## Turn on batches and connect the site

After both pilot checks pass, set `MODE = 'survey'`, `PILOT_VERIFIED = True`, and keep one batch of 10–50 products for the first scale check. In the saved notebook's **Settings → Schedule a notebook to run**, set a recurring time only if the control is available and the account permits it. Review the first scheduled run, including access to the attached secrets. A subsequent benchmark can add batches up to an aggregate 1,000 products as measured time, transfer, and storage permit. Keep it unscheduled during benchmarking. Divide the archive inventory by measured unique products per successful session to estimate duration, then account separately for the fraction of useful epochs and completed motion groups.

The worker interleaves anonymous [public DR1 and QR3 listings](https://irsa.ipac.caltech.edu/cloud_access/#spherex), commits an inventory cursor per page, validates native products, and queues selected groups that overlap, cover the requested sky patch, and pass time, detector, calibration, and wavelength checks. It prioritizes one queued owner request per scheduled session. Motion search reads FITS ranges and runs the existing DeepTrace code. The public search result lists retained peaks with observation and trial evidence. A bounded Gaia/JPL check can attach a preliminary association for review.

To connect the updated frontend, add `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` to **SLOWTRACE X → Settings → Environment Variables** in the confirmed Hobby project, then deploy the updated source. The Vercel API uses the publishable key on the server. The browser calls the website's API and never receives the key. The Kaggle worker's elevated key stays in Kaggle Secrets. Review **Statistics → Remote survey** for the latest committed counts and resource measurements. In **Observe → Automatic detection**, sign in with the allowlisted Auth account and choose **Queue this field**. Keep the returned status link. The search runs when the saved Kaggle notebook next runs, and the link is shareable. A bounded result can be incomplete if the selected sample lacks compatible epochs.

The prior 500-image published snapshot stays separate. Future archive coverage and catalog identification depend on compatible epochs, sky sampling, data quality, and compute and storage availability. The current planner examines a bounded subset of spatially overlapping patches, and candidate counts measure retained trial peaks. Survey-wide completeness, exhaustive stellar classification, and independent discovery confirmation require additional validation. Kaggle and Supabase do not guarantee enough lifetime free capacity to finish the archive.
